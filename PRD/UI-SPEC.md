# Beauty CRM｜UI-SPEC v1.0

> 原型狀態：2026-09-21｜對齊 `PRD/SPEC.md` v3.0.2，僅供 UI prototype review，尚未進入 React 實作。

## 1. 設計決策

Beauty CRM 的核心不是「再做一個預約 / POS 後台」，而是讓設計師每次服務後，能在 30 秒內留下足夠的記憶，並在適合的時間採取下一步。因此首頁只回答三件事：

1. 今天先聯絡誰？
2. 上次幫她做了什麼，有沒有不能踩的雷？
3. 下一步是建立服務紀錄、調整回訪日，還是人工核准一則訊息？

### 與既有 v0.4.0 設計的差異

| 項目 | 既有方向 | 本版補強 |
|---|---|---|
| IA | 7 個平行 admin 分頁 | 5 個主入口；推播收進「回訪」流程，避免變成自動行銷工具 |
| 首頁 | greeting + 統計卡 | 「今日回訪工作台」為主，統計只服務決策 |
| 客戶資訊 | 客戶列表與摘要分開 | 回訪清單旁固定顯示客戶記憶摘要，減少來回切頁 |
| 回訪 | 顯示日期與狀態 | 顯示逾期天數、建議理由、可覆寫日期與下一步 |
| 推播 | 另立一個 broadcast tab | 草稿在回訪卡片內產生；明確顯示「未核准，不會送出」 |
| 手機 | bottom nav + add sheet | bottom nav 保留；新增服務固定為單手可完成的 bottom sheet |

## 2. 資訊架構

```text
今日工作台
├── 回訪佇列：逾期 / 3 天內 / 本週已完成
├── 客戶記憶摘要：上次服務、偏好、過敏、同意狀態
├── 回流漏斗：應回訪 → 已聯絡 → 已預約
└── 快速新增服務紀錄

客戶
├── 搜尋與標籤
├── 客戶詳情
└── 療程時間軸 / 照片 / 可攜資料

回訪
├── 依逾期天數排序
├── 產生草稿
└── 人工核准 / 標記已聯絡 / 標記已預約

洞察
└── 回流率、營收、VIP 觸發原因

設定
└── 週期模板、加密匯出、刪除資料、裝置警告
```

## 3. 首頁工作台規格

### 3.1 上方區

- 左側：`早安，林心妍` + 今日一句可行動摘要，例如「3 位客戶已超過建議回訪日」。
- 右側：`＋ 新增服務紀錄` 為唯一主要 CTA；通知與帳號為次要操作。
- 首屏保留 4 個輕量指標：待回訪、3 天內、已預約、月營收。數字必須能導向列表或操作。

### 3.2 回訪佇列

- 預設排序：逾期天數由高到低。
- 每列至少顯示：姓名、服務項目、上次日期、建議回訪日、逾期天數、同意狀態。
- 點選一列後，右側顯示「客戶記憶」：偏好、過敏、上次備註、累計消費、VIP 觸發原因。
- 主操作：`產生草稿`、`調整回訪日`、`標記已聯絡`。
- 若 consent 不是 `granted`，不可顯示發送動作，只能顯示「需先取得同意」。

### 3.3 草稿核准

- 草稿在同一張回訪卡內展開，不跳到另一頁。
- 顯示明確狀態：`草稿`、`已核准`、`已聯絡`。
- 固定提示：「這是草稿；未按核准前，不會送出任何訊息。」
- `核准草稿` 只代表設計師確認內容，不等於自動發送；第一版提供複製 / 開啟 LINE 的下一步。

## 4. 快速新增服務紀錄（FR-010）

- Desktop：右側 drawer；Mobile：bottom sheet。
- 欄位順序：客戶 → 服務項目 → 產品 / 成分 → 服務日期 → 下次回訪日 → 備註。
- 服務類別選擇後帶入週期模板，但日期永遠可手動覆寫。
- 偵測到過敏或禁忌時，使用 `role=alert` 的高對比警示，必須勾選「已知風險，繼續」才能儲存。
- 儲存成功後回到原本清單，顯示一行可撤銷的成功提示；不得把使用者丟到空白頁。

## 5. 視覺系統

### 色彩

- 背景：`#FDF7F2`；內容表面：`#FFFFFF`；側欄：`#2D2926`。
- 主色：`#B85A45`；主色淡底：`#F5E3DA`。
- 文字：`#2A2421` / `#756B65`；警示：`#B85A45`，成功：`#477A5B`，危險：`#B33A2A`。
- 任何狀態不得只靠色彩表達，必須同時有文字或圖示語意。

### 版型

- Desktop ≥ 1024：240px 深色側欄 + 內容最大寬 1180px。
- Tablet 768–1023：側欄折疊成 top bar，內容單欄。
- Mobile < 768：top bar + bottom nav；主要內容預留 80px 底部空間。
- 卡片圓角 16px；按鈕與輸入框 10px；避免每個區塊都套邊框，讓重要內容有層次。

## 6. Prototype review acceptance criteria

- [ ] 進入首頁 5 秒內能找到「今天先聯絡誰」。
- [ ] 點選回訪客戶後，不切頁即可看到上次服務、過敏、偏好與下一步。
- [ ] 未取得行銷同意的客戶，不出現可送出訊息的 CTA。
- [ ] 草稿未核准前，介面清楚表達不會送出。
- [ ] 新增服務紀錄可在 desktop drawer / mobile bottom sheet 完成。
- [ ] 過敏衝突會阻擋儲存，且不清掉已輸入資料。
- [ ] 回訪日可從模板自動帶入，也可手動覆寫。
- [ ] 390px 寬度不出現橫向溢位；主要 CTA 仍可單手觸達。
